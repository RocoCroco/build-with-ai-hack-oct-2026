Workout Draw: app map

A pocket guide to how the app is put together, where things live, and where to start when you want to change something. A snapshot of the code at the commit listed at the bottom; it can drift as the app changes.

What it is

A phone-sized web app that runs entirely in the browser. You set up a workout (time wheel, body map, gym or home), every exercise is revealed by a case-opening roll, and you get a plan you can share, follow set by set, and save. Finished workouts grow a stickman on the Start screen and fill out a 7-sided balance chart. Nothing is sent to a server: history lives in this browser.

  • Screenssrc/screens/, one component per step, chosen in src/App.tsx
  • The draw statesrc/lib/drawState.ts: one reducer for the whole journey, from Start to Done
  • Exercise datasrc/data/: exercises, form cues, and every animated figure's poses
  • Savingsrc/lib/storage.ts: the one place that talks to localStorage
  • Animation enginessrc/lib/figure.ts (exercise figures), src/lib/muscleMan.ts (the stickman), src/lib/useFrameLoop.ts

One action, end to end: tap the stickman

The route through the code Reference route

Not toured step by step together; open these to follow the tap yourself. Search for the names in quotes.

  1. The tap lands: src/screens/MuscleMan.tsx

    Search function tap(). It ignores the tap if he's already busy (a celebration or another move), picks a random move, and switches his "mode" to it. The SVG's onClick in ManFigure calls it.

  2. What he can do: src/lib/muscleMan.ts

    Search TAP_MOVES: the 3 dances (stanky leg, disco, griddy) and 5 poses, each a list of beats (a pose, how long to move into it, how long to hold). pickTapMove never repeats the last move; playBeats says which pose he's in at any moment.

  3. The heartbeat: src/lib/useFrameLoop.ts

    Search useFrameLoop. One requestAnimationFrame loop that subscribes once and always calls the latest code. This replaced Motion's useAnimationFrame, which re-subscribed on every redraw and stopped the stickman after a few frames.

    Show the core of it 
    const loop = (t: number) => {
  start ??= t;
  latest.current((t - start) / 1000);
  id = requestAnimationFrame(loop);
};
id = requestAnimationFrame(loop);
return () => cancelAnimationFrame(id);

A practice to reuse

When a check lets you down, turn the corrected check into a skill.

The stickman looked right in still screenshots, but in the real app he was frozen. Stills (and headless browsers in "virtual time") only render a few frames, so they couldn't show that the frame loop had stopped. What settled it was sampling his arm position every second in a really running browser, with a real tap. That procedure is now a project skill, .claude/skills/animation-check/SKILL.md (with scripts/probe.mjs), that triggers when someone reports an animation isn't working and only accepts "fixed" once sampled numbers show the motion.

On another project: when the agent claims something works and it doesn't, note what evidence would have caught it, then write that down as a skill with a narrow trigger (the description) and a clear bar for "done". The next time, the agent brings the right check on its own.
